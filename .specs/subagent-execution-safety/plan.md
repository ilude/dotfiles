# Plan: Simplify and Contain Pi Subagent Execution

## Objective

Replace the overloaded Pi subagent role and write-lease interface with explicit read, write, and coordinator operations; use advisory work markers instead of exclusive repository locks; constrain each leaf's governed file and recursive-search activity to a parent-selected workspace; add non-disruptive liveness inspection and recoverable tool interruption; and make the resulting behavior measurable through portable structured telemetry while preserving root-only Onclave participation.

## Completion Evidence

- Evidence: New model-facing calls cannot express coordinator/leaf field conflicts; overlapping modifying workers run and report advisory overlap; a parent can dispatch a leaf to either its own or another explicit workspace; governed native tools and recognized recursive searches reject escape from that workspace; a timed-out or operator-interrupted tool settles its child process tree and resumes the persisted child session with an explicit unknown-outcome recovery message; quiet, unresponsive, and tool-stalled runs are distinguishable; coordinator budgets return bounded partial results; legacy resumed calls still execute through one adapter; child processes do not initialize Onclave; and versioned JSONL metrics flatten into tested DuckDB views usable by Python dataframe tooling.
- Fails when: The implementation retains mandatory write scopes or lease-based overlap rejection, permits new calls to combine incompatible roles and fields, claims arbitrary shell execution is sandboxed, loses the persisted child context during hung-tool recovery, assumes interrupted tool side effects succeeded, persists raw prompts/commands/paths in metrics, loses legacy resumed calls, or allows a coordinator or leaf to reserve an Onclave connection.

## Boundaries

- Pi owns the runtime, tools, workspace policy, watchdog, control transport, status, telemetry, analytics views, guidance, and compatibility adapter under `pi/`.
- `modules/onclave/` owns direct verification that its Pi adapter exits before registration, polling, or heartbeat startup in child processes; keep the checkout on `feature/v2-broker-core`, validate it independently, and keep `pi/extensions/onclave-pi.ts` as a thin loader.
- Expose `subagent_read`, `subagent_write`, and `subagent_coordinate`. Each uses one item-array shape for single or parallel work. Tool choice, not agent name or optional `role`, determines authority. Read execution uses a closed positive tool allowlist independent of agent configuration or later extension registration; an unrecognized tool is unavailable rather than presumed safe.
- `workspaceRoot` defaults to the parent's current workspace root and may be replaced by the parent with another existing non-filesystem-root directory. A child cannot widen it. Resolve the target workspace before agent discovery, then independently rebuild its instruction context, trust decision, project-agent catalog, `agentScope`, and project-agent confirmation boundary. `workPaths` and coordinator `workBoundary` are visible advisory markers only; overlap or departure is reported and never blocks, queues, or removes shell tools. Update Pi delegation guidance to prefer separate markers when practical while allowing and reporting intentional overlap.
- Read leaves have no raw shell. Write leaves retain shell for builds and tests. Native path tools and statically resolvable recursive `rg`, `grep -R`, and `find` targets are checked against `workspaceRoot`; unresolved dynamic recursive targets are rejected. Other arbitrary shell programs are explicitly not an OS sandbox.
- Recognized recursive searches use the existing 120-second command convention unless the caller supplies a bounded override. Tool timeout or `interrupt_tool` settles the child process tree, preserves its persisted session reference, and launches a replacement child from that session with an explicit message that the interrupted tool outcome and side effects are unknown. Quiet watchdogs ping and classify but do not auto-cancel.
- Coordinator defaults are `maxWorkers: 6`, `maxTurns: 32`, and `softDeadlineMs: 900000`; reaching a budget returns a partial result and gaps from a persistent coordinator session.
- Runtime ping is authenticated transport control, not a model message or turn. Reuse broker credentials and bind every recovery request to the exact parent-child relationship, run ID, active tool-call ID, persisted session path, and freshness value; reject sibling, stale, replayed, wrong-run, and invalid-token requests. Successful interruption requires bounded verified child process-tree settlement, output-stream closure, and removal of the matching live binding before relaunching from the persisted session. An unacknowledged, stale, mismatched, unsettled, or sessionless interruption returns a distinct typed outcome. Recovery never assumes the interrupted tool or its side effects completed.
- Keep `subagent`, `subagent_chain`, `subagent_continue`, `subagent_fanout`, and `subagent_workflow` registered but hidden for resumed sessions. Their historical single, parallel, chain, continuation, fan-out, workflow, background, role/scope, task-link, and legacy output forms translate through one compatibility adapter; leaf `scope` becomes `workPaths`, coordinator `scope` becomes `workBoundary`, old single/parallel shapes become item arrays, and historical agent-name role inference exists only in this adapter.
- Keep durable task persistence, dependencies, lifecycle, and root ownership unchanged. Place the existing `taskId` on each worker or coordinator; resolve `workspaceRoot` before validating that task in the effective workspace; automatically link only when exactly one running root-owned task is unambiguous; return bounded current-workspace choices for invalid references; and let the compatibility adapter map historical top-level and per-item linkage. Children never create, select among several, transition, or complete tasks.
- Extend the existing allowlisted orchestration telemetry instead of adding a logging framework. Persist one closeout event plus sparse intervention events; never persist raw task text, commands, output, workspace paths, or work paths.
- Onclave eligibility requires a root-only capability that child launch paths explicitly strip, not only mutable child markers. Child markers remain defense-in-depth and diagnostics. A nested Pi launched by a write leaf after removing those markers must still be ineligible to initialize Onclave.
- Advanced chain, continuation, fan-out, and typed workflow schemas are not redesigned in this change. They reuse the new internal execution, workspace, activity, and telemetry contracts while retaining their current external compatibility surface.
