### Safety systems

- Damage control fails closed on missing or invalid policy and intercepts registered tool calls before execution. [source: `pi/README.md:209`; `pi/README.md:296-300`]
- Damage control covers dangerous commands, sensitive paths, protected files, semantic Git, scoped deletion, symlinks, glob containment, taint sequences, secret output, and repeated tool loops. [source: `pi/README.md:301-313`]
- Session budget gates repeated same-agent delegation and repeated identical command failures while leaving elapsed time and tool count informational. [source: `pi/docs/session-budget.md:13-18`]
- `text_edit` and `structured_edit` enforce repository containment, ignored and secret-path rejection, expected matches, and bounded previews. [source: `pi/extensions/README.md:139-148`]
- Commit tools bind plans and staged state through opaque handles, revalidate exact paths and index state, scan secrets, and prohibit force push. [source: `pi/extensions/README.md:228-247`]
- Quality gates run only bounded settlement-safe validators; explicit-only, project, long-running, and complexity checks remain outside automatic settlement. [source: `pi/README.md:344-347`]
- Worktree occupancy warns about concurrent writers but intentionally does not block the session. [source: `pi/README.md:564-575`]
- Transcript tracing deep-clones and redacts headers, sensitive field names, free text, and known token patterns before disk writes, and refuses cloud-sync paths. [source: `pi/README.md:920-934`]

## 2. Architecture principles stated in docs

- Ownership boundary: Pi workflow, runtime, safety, routing, status, and tools belong under `pi/`; unrelated application work does not authorize changes there. [source: `pi/AGENTS.md:36-40`]
- Source-state boundary: curated source and configuration are tracked, while sessions, logs, caches, indexes, local events, and tool state remain uncommitted. [source: `pi/AGENTS.md:40`; `pi/README.md:230-245`]
- Minimal deterministic workflow: prefer maintained deterministic mechanisms, keep instructions flexible, and do not add tracking unless explicitly requested or required by the active workflow. [source: `pi/AGENTS.md:12`; `pi/AGENTS.md:24`]
- Delegation boundary: work directly on one coherent task and delegate only for independent work, specialization, verification independence, or context isolation. [source: `pi/README.md:796`; `pi/AGENTS.md:34`]
- Task versus subagent: `task` is the sole owner of durable todo and dependency records; `subagent` owns transient child execution and may only correlate with an existing task. [source: `pi/README.md:579-594`]
- Parent responsibility: the parent selects ready tasks, marks them running, dispatches work, validates results, and records terminal state; the task tool never executes or manages processes. [source: `pi/README.md:630-637`]
- Damage-control authority: direct bounded user requests authorize in-scope work, but unresolved credible unintended consequences stop execution unless damage control already gates them. [source: `pi/AGENTS.md:16`]
- Damage-control implementation: policy loading, pure engine decisions, state, evaluation, judge, and debug logging are separated from the Pi event adapter. [source: `pi/extensions/README.md:185-187`]
- Routing authority: the provider route is authoritative after explicit overrides, continuation holds, downgrade intent, context-window floors, trust boundaries, and route-state fallback. [source: `pi/README.md:671-689`]
- User overrides: explicit routing and model choices remain authoritative and must not silently cross provider families. [source: `pi/README.md:682-684`; `pi/prompt-routing/docs/operator-handoff.md:24-39`]
- Command placement: static prompt commands belong in `pi/prompts`, reusable guidance in `pi/skills`, and state, UI, Git, or lifecycle behavior in TypeScript extensions. [source: `pi/extensions/README.md:68-83`]
- Extension boundary: helper and library code belongs under `pi/lib` because every top-level TypeScript file in `pi/extensions` is auto-discovered. [source: `pi/extensions/README.md:13-30`]
- Expertise boundary: expertise JSONL is runtime data, not an instruction surface; durable guidance belongs in `AGENTS.md`, skills, or tracked docs. [source: `pi/docs/expertise-layering.md:3`; `pi/docs/expertise-layering.md:45-52`]

## 4. Documented but unfinished or evidence-gated features

- Damage-control shadow judging is disabled by default, has no execution authority, and requires at least 100 events, 95 percent approval agreement, and zero dangerous judge-allows before a separate authority decision. [source: `pi/README.md:312-317`]
- `readOnlyFanout` is an opt-in experiment; its output-schema validation proves structure only, not factual correctness, task quality, or user value. [source: `pi/docs/orchestration-telemetry.md:121-130`; `pi/docs/orchestration-telemetry.md:156-172`]
- Codex routing outcome sampling covers 10 percent of eligible policy dispatches by default, excludes explicit overrides and continued sessions, and records validation as unavailable when no structured contract exists. [source: `pi/docs/orchestration-telemetry.md:105-117`]
- Sidecar tracing is implemented but default off, and the optional streaming heartbeat remains disabled. [source: `pi/README.md:868`; `pi/README.md:908`; `pi/README.md:965`]
- Expertise indexing and retrieval exist locally, but retrieval is not exposed as an agent tool and `read_expertise` and `append_expertise` are unavailable. [source: `pi/docs/expertise-layering.md:23-33`; `pi/docs/expertise-layering.md:45`]
- Rejected and deferred watchdog sensors are preserved only in an archived plan with evidence requirements for reconsideration. [source: `pi/docs/session-budget.md:74-86`]
- Workflow dispatch telemetry records only command start facts and does not establish implementation, validation, review, blocker, or archive completion. [source: `pi/docs/workflow-eval-telemetry.md:3`; `pi/docs/workflow-eval-telemetry.md:20-54`]
- Orchestration telemetry is observational; causal savings require matched cohorts outside its schema. [source: `pi/docs/orchestration-telemetry.md:264-268`]
- Metrics have no built-in retention or purge job. [source: `pi/README.md:485`]
- Scheduled prompts and managed background processes survive session replacement only within the current Pi process and stop at process exit. [source: `pi/README.md:323-327`; `pi/README.md:416-420`]
- Task batch graph validation is preflighted but publication is not transactional and requires explicit cleanup after partial write failure. [source: `pi/README.md:637`]
- `skill-review-command.ts` contains generator logic but its default extension is empty, consistent with the documented retirement of `/skill-review`. [source: `pi/extensions/skill-review-command.ts:109-173`; `pi/README.md:479`]

## 7. Gaps the docs themselves acknowledge

- Telemetry measures behavior but not causality: orchestration records cannot establish savings without matched cohorts. [source: `pi/docs/orchestration-telemetry.md:264-268`]
- Experiment validation is structural only and does not establish factual correctness, task quality, or user acceptance. [source: `pi/docs/orchestration-telemetry.md:156-172`]
- Workflow telemetry has no completion semantics beyond dispatch start. [source: `pi/docs/workflow-eval-telemetry.md:20-54`]
- Metrics lack automatic retention and purge. [source: `pi/README.md:485`]
- Costs can be unavailable and must not be interpreted as zero. [source: `pi/docs/orchestration-telemetry.md:264-265`]
- Expertise retrieval is local but unavailable to agents, and legacy snapshots are retired. [source: `pi/docs/expertise-layering.md:33-45`; `pi/docs/expertise-layering.md:63`]
- Watchdog time and tool-count sensors were removed because duration alone did not show scope drift; other rejected sensors remain deferred pending evidence. [source: `pi/docs/session-budget.md:74-86`]
- Newly refreshed Codex models may exist before tracked startup `enabledModels` includes them. [source: `pi/README.md:551-552`]
- Task batch publication can partially succeed and has no automatic rollback. [source: `pi/README.md:637`]
- Background terminals and scheduler jobs are process-local rather than durable across Pi exits. [source: `pi/README.md:323-327`; `pi/README.md:416-420`]
- Shadow judging remains non-authoritative and evidence-gated. [source: `pi/README.md:312-317`]
- Documentation says `operator-status.ts` adds `/doctor`, but the local file registers only lifecycle hooks and status rendering; no local `registerCommand("doctor", ...)` exists. This may depend on upstream Pi or the external Onclave adapter, but local source does not establish that owner. [source: `pi/README.md:596-619`; `pi/extensions/operator-status.ts:490-508`]
- The commit fixture documentation says `commit_push` is deferred, but active source and the extension README register and document it. The fixture note appears stale. [source: `pi/tests/fixtures/commit/README.md:5-10`; `pi/extensions/commit.ts:238-245`; `pi/extensions/README.md:233-245`]
- The README describes `skills/shared/` and `skills/pi-skills/` community packages, but those paths were absent from the inspected repository skill listing. Their installed runtime presence cannot be established from tracked source alone. [source: `pi/README.md:850-862`; `pi/skills/`]
