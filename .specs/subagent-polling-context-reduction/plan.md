# Prevent Subagent Polling and Context Pollution

## Objective

Prevent provider turns from repeatedly polling subagent status, deliver abnormal subagent state only when it changes, and bound noisy subagent and command results before they enter the parent model context. Preserve exact completion delivery, recovery authority, failure evidence, full recoverable output, and stable ordinary-turn tool visibility.

## Completion Evidence

- Evidence: Hook-integrated tests show that an unchanged exact-process or orchestration status check is blocked before a second inspection can create a polling loop; an internally detected transition to `stalled-tool`, `unresponsive-runtime`, or `dead-process` schedules one bounded follow-up containing the exact recovery evidence while normal scans schedule no provider turn; normal background completion makes one successful `sendMessage` call per queued completion within the process; oversized foreground, parallel, and background subagent results expose a bounded head/tail handoff plus a private full-output artifact; and large Bash and `pwsh` command results with a matching reduction rule are reduced before their first provider request while small, unmatched, source-read, and failed-artifact cases retain their current safe behavior. Existing orchestration telemetry continues to report byte-accurate parent-visible and artifact sizes.
- Fails when: Unchanged status can be called repeatedly, normal or `responsive-quiet` work schedules a provider turn, watchdog delivery repeats without a semantic state transition, a queued completion makes zero or multiple successful `sendMessage` calls in one process, recovery lacks the exact process/activity/tool evidence it requires, output is discarded without a usable artifact, ordinary small results change, source reads are eagerly reduced, eager reduction rewrites an already-visible result, or the primary worktree's existing `pi/extensions/codex-status.ts`, `pi/lib/metrics.ts`, or `pi/tests/metrics.test.ts` changes are touched.

## Boundaries and Assumptions

- Planning is complete in primary `.specs/subagent-polling-context-reduction/plan.md`. `/do-it` must materialize this spec in its owned `workflow/subagent-polling-context-reduction` worktree before implementation.
- The primary worktree and its existing modified files remain untouched. No task requires the cache telemetry files currently modified there.
- Keep `subagent_status` root-only, keep `/subagents` as the operator listing and cancellation surface, and preserve exact-process recovery through `subagent_control`.
- Keep the `subagent_status` tool schema stable across ordinary turns. The watchdog is an in-process timer over existing run snapshots and broker pings; it must not poll through provider calls, persist new lifecycle state, or emit normal-progress messages.
- Do not add a model summarization pass or a new public output mode. Small inline results and explicit `file-only` behavior remain compatible. Oversized output uses deterministic bounding plus the existing private artifact mechanism.
- Do not eagerly reduce `read`, web, or subagent tool results through the generic command reducer. Subagent handoff is bounded by its owning extension; exact source content remains available through `read` offsets and limits.
- Update `pi/skills/pi-extension/references/contracts/subagents-and-tasks.md` only for accepted callable status, watchdog, and provider-visible subagent-result behavior. The existing cache-friendly contract remains unchanged because ordinary tool visibility does not change.
