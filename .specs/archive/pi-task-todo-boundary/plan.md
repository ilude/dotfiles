# Plan: Make Task a Durable Todo and Dependency Surface

Status: Complete

## Outcome

Refactor Pi's `task` tool into a durable todo and dependency-tracking surface that survives context compaction without owning subagent execution, background processes, waiting, output capture, or scheduling. Keep `schedule` as the independent process-local time trigger, then apply the remaining low-risk active-schema reductions.

## Boundaries and safety

- Preserve `task` creation, batch creation, updates, removal, listing, lookup, state tracking, `blockedBy`, `blockedByKeys`, `scope`, workspace isolation, persistence, and `/tasks` navigation.
- Do not add claims, leases, access modes, scope locks, automatic dispatch, a task-record schema migration, or a replacement workflow engine.
- Do not merge `task`, `subagent`, background terminals, or `schedule`. The parent agent remains responsible for the sequence `task ready -> task update state=running -> subagent or bg_start -> task update terminal state`.
- Do not change schedule storage or runtime behavior. Schedule remains process-local and only emits later or recurring prompts.
- Keep existing task JSON readable and do not rewrite, delete, or migrate `~/.pi/agent/operator/tasks`. The planning audit found 334 valid records, 19 with legacy execution metadata, and no running legacy execution. Recheck this structural condition before removing live execution; stop if a running execution record exists.
- Preserve historical task execution metadata and telemetry parsing as inert compatibility data, but do not advertise, create, restart, or execute it.
- Preserve the current uncommitted `/context`, subagent schema, and tool-discovery improvements. Do not touch `.specs/rootless-podman-quadlet-hardening/`.
- Rollback is code-only: restore the changed Pi files. Persisted task records and old task output artifacts must remain untouched.
