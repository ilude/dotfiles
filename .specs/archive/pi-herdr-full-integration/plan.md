# Plan: Complete the Pi and Herdr Integration

Status: Complete

## Outcome

Complete the remaining Herdr integration by adding opt-in Pi-native Herdr control tools and privacy-safe Pi sidebar metadata while preserving Pi's existing orchestration and all behavior outside Herdr.

## Current status

Herdr `0.8.0-preview.2026-08-04-d78e3d3b5126`, Pi `0.84.1`, and official Pi integration v8 are installed. The official integration owns semantic lifecycle state, `ask_user` reports blocked state, and `/branch`, `/new-instance`, `/new-terminal`, and Ctrl+T already route through Herdr when managed. The remaining scope is control tools plus display-only metadata.

## Boundaries and safety

- Keep Pi's `subagent`, `task`, and background-terminal systems as the structured orchestration plane. Installing Herdr tools must not redirect ordinary delegation or background work into visible panes.
- Use Herdr tools only when the user explicitly mentions Herdr or asks to inspect or control it. Do not add worktree automation, notifications, pane-backed local subagents, or a visible `bg_start` mode.
- Do not edit `pi/extensions/herdr-agent-state.ts`; it is managed by Herdr and remains the sole lifecycle authority. Custom metadata must use `pane report-metadata`, never `report-agent` or `report-agent-session`.
- Report only model ID, context percentage, and aggregate running-subagent and running/blocked-task counts. Do not report prompts, task summaries, paths, repository names, or transcript content.
- The generated Pi package cache under `~/.pi/agent/npm/` remains untracked. Do not add the package to `pi/package.json` or `pi/pnpm-lock.yaml`; Pi package installation is owned by `pi/settings.json`.
- Existing unrelated task-registry and documentation changes are out of scope and must not be modified or reverted.
- The live Herdr target is the current user's `%APPDATA%\herdr\config.toml` and running default Herdr server. Do not create a backup. If `herdr config check` or `herdr server reload-config` fails, stop, remove only the new Pi sidebar table, reload the prior terminal-only config, and leave tracked rollback to Git. Package/extension rollback is removal of the pinned package setting and custom metadata extension followed by Pi reload.
