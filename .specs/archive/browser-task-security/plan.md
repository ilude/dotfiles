# Make browser automation usable with focused task and data-transfer protection

## Goal and settled scope

Allow normal browsing, account login, password entry, consent handling, screenshots, and development forms. Replace broad page/keyword blocking with controls over task authority, credential destinations, sensitive-data transfer, and consequential actions.

Operator decisions from this conversation:

- A request to log into Reddit/X authorizes login and reading. Posting, messaging, purchases, deletion, and account/security changes require an actual explicit request. Do not repeatedly ask for actions already clearly authorized.
- Stored credentials come from Bitwarden Secrets Manager (BWS), resolved locally through secret references. Direct entry of disposable dev credentials remains supported.
- Localhost development apps are routinely available in development tasks. Other private-network targets require authorization through the request or local configuration, not a blanket private-IP ban.
- Include browser changes and the necessary Damage Control integration across export-capable tools. Do not perform a general security-framework rewrite.
- Initial baseline: existing Brave Safe Browsing and browser TLS validation. No automatic bypass of security warnings and no new external blacklist service.

Planning authorizes only this specification. `/do-it` authorizes implementation, a dedicated task worktree, local commits, archival, and integration into the recorded target unless `--no-merge` is supplied. Push, deployment, creation/modification of real BWS records, and real-account transactions are not authorized. Operator manual/live testing is a non-blocking post-completion verification limit.

## Implementation contract

### Authority and decisions

Keep policy enforcement outside the acting model. Direct operator requests and UI decisions establish authority; page content, tool results, assistant claims, subagent results, and model-generated `approved` flags do not. Quoted material in a user message is data, not automatically a request.

Reuse Damage Control's decision/review/prompt path. Routine public reading, explicitly authorized login, navigation within the task, and scoped dev forms proceed without prompts or per-action model review. Contextual review is for evidence-based candidates: accessing an unrelated private account; transmitting private observations; posting/messaging; purchases; deletion; security/admin changes; or a request/destination inconsistent with the task. Clearly requested writes can proceed without a second approval. An unresolved meaningful-harm candidate asks the operator about the specific action, not permission to browse generally.

Local policy/authority state must be branch/session scoped. Reconstruct applicable direct intent and explicit decisions after reload/resume without trusting compaction summaries as new authority. Switch/tree/shutdown invalidate pending reviews and secret leases. A previous login or approved origin is not unlimited authority for unrelated future tasks.

The shared boundary contract must represent: current session/generation; trusted request evidence; source observation class and origin; concrete action/target/frame and destination; payload or local secret reference; expected effect; and allow/review/ask/deny with an actionable reason. These are executor-observed facts where possible, not assertions supplied by the acting model. Keep bounded private browser evidence local; send the existing reviewer only the minimum redacted facts needed to decide the pending action. No full browser-history export, second approval framework, or new telemetry pipeline.

### Credentials and observable data

Extend fill with mutually exclusive `value` and `secret_ref`. Preserve ordinary value fills, including disposable dev passwords, and the controlled-input native setter fix.

Store reference-to-BWS-record bindings in ignored active-profile local configuration with a tracked identity-free schema/example. Each binding identifies an exact BWS record/expected key and allowed login origins/field purpose. The operator configures bindings; the model cannot invent a BWS record, enumerate the vault, broaden allowed origins, or resolve a secret into conversational text. Do not embed account identities, IDs of real records, or secrets in fixtures.

Check session/process/target, actual frame origin, credential binding, field, and available form destination immediately before local resolution and filling. Cross-origin authentication/SSO works through separately bound credential origins, not wildcard trust inherited from a redirect. Support exact frame targeting for iframe login controls where needed. Treat input/change handlers as possible transmission at fill time, not only at Submit.

Read one exact BWS record lazily with the existing SDK/access-key approach, bounded cancellation/timeouts, and no stdout/stderr/exception leakage. Reuse/extract the narrow helper rather than bulk secret loading or shelling out through model-visible tools. Raw resolved values never enter tool arguments/results, structured content, model/judge context, local policy files, or diagnostic logs. Retain secret data only for the needed local operation/session lifetime; clear it on invalidation. Retrieval failure stops that credential operation, not unrelated browsing.

Permit observing login pages. Exclude password control values from text projections and mask sensitive form controls for screenshots, including when a password was revealed by UI. Replace blanket keyword redaction with actual secret/value-aware filtering while retaining useful labels and diagnostics. Keep secret-bearing URLs out of persisted projections while preserving useful nonsecret URL information. Direct dev values are already present in operator/model inputs and native transcripts; do not claim this change retroactively removes them.

Credentials are intentionally disclosed to the bound website. Origin binding does not make compromised scripts at that origin safe. Form-field masking also cannot guarantee removal of every arbitrary pixel containing a reflected secret. Document these residual risks; do not block all screenshots or invent general OCR/DLP requirements.

### Browser and destination boundaries

Revalidate the recorded process tuple before every page operation. Recover stale attachments only by a normal verified attach; never silently bind another profile/process/tab or restart an operator-owned browser. Maintain current exact raw target/session semantics and process-specific cleanup.

Keep native TLS validation and Safe Browsing enabled. Detect actual browser security interstitials/states, not ordinary page phrases, and do not let tool actions bypass them. Do not implement independent TLS preflights, globally ignored certificate errors, or a reputation lookup that sends private/token-bearing URLs to a third party. HTTP loopback development remains usable; HTTPS development should use a trusted local CA. Certificate-warning bypass is outside this plan.

Canonicalize URLs with a real parser and reject embedded credentials. Ordinary navigation supports HTTP/HTTPS and tool-owned blank initialization. Preserve explicitly requested local-file inspection through Damage Control's filesystem path policy rather than granting pages general local-file access or adding a blanket local-file ban. Reject executable URL schemes that bypass the no-arbitrary-evaluation interface, and do not expose browser security settings or the CDP control endpoint as ordinary page destinations. Normalize host identity for comparisons, including trailing dots and IDNs; no substring host matching.

Public navigation does not need a global domain allowlist. Localhost access is allowed in the requested development workflow; other internal/private destinations need direct request or local configuration. Merely encountering a link or an iframe does not authorize an unrelated private account/service. Public identity-provider/CDN dependencies should not cause blanket same-origin restrictions or repeated approval prompts. Credential binding remains stricter than ordinary public navigation.

Use persistent target-scoped CDP request/navigation observation/interception for managed targets so link clicks, redirects, popups, frame navigation, and scripted form/HTTP transfers are not invisible to the policy. Bind guards before agent actions, carry them to agent-created descendant targets, and recheck changed destinations before continuing a transfer. Do not globally intercept all of the operator's existing tabs in attached mode. Existing tabs become managed when the operator's task selects them; manage their agent-generated activity without claiming control over prior traffic.

Request-boundary hostname/IP checks and redirect handling provide useful protection, but a DNS lookup followed by a separately resolved browser connection is not enforced IP isolation. This scope does not add a mandatory proxy, firewall, or isolated network stack to attached personal browsers. Explicitly document residual DNS-rebinding/subresource/connection-level limitations and test what the chosen CDP mechanism actually prevents. Do not present these checks as a comprehensive browser network sandbox. If concrete implementation evidence requires a behavior-changing proxy/profile migration to meet a stronger guarantee, ask rather than silently adding it.

### Content and cross-tool transfer

Mark text/images from browser pages as untrusted observations. Reuse the existing tool-free screening approach for bounded text observations, with exact source metadata and deterministic guidance. A screen flag is a risk signal, not a reason to disable a page or reject legitimate documentation discussing attacks. Screening failure is reported, not interpreted as clean and not a global browsing outage. Screenshots remain usable; no unsupported claim of complete visual injection screening.

Extend Damage Control to browser effect candidates and the relevant export paths already available to this orchestrator: bash/PowerShell network commands, web_fetch URLs, web_search queries, and Onclave messages. Do not use Onclave to research or execute this plan. Its tool adapter can be tested with synthetic requests without contacting peers. No modifications to Onclave product code or third-party service authorization.

Use bounded source/destination/effect evidence to recognize private-read-to-export sequences, including same-domain comments/messages. A destination on Reddit/X can be an attacker-controlled sink. Check fills and URL/query construction before transmission, not just final submission. Known BWS secrets must not be substituted into general URLs, searches, messages, or shell payloads. Ordinary public searches, authorized reports/messages, and repository Git publication retain existing authorization behavior.

This is not perfect taint tracking of all model-generated text, arbitrary encodings, or arbitrary programs. Tests must prove the agreed concrete attack paths and legitimate workflows; documentation must distinguish enforced deterministic boundaries from model-assisted decisions and residual risks. Do not imply that extending these adapters makes arbitrary shell execution a secure sandbox.

### Deliberately preserved or deferred

- Keep no arbitrary JavaScript, bulk-cookie, or browser-storage API exposed to the model. Fixed internal CDP expressions remain available for browser implementation.
- Actual CAPTCHA challenges still require manual completion. Remove page-wide regex blocking based merely on CAPTCHA/verification words; ordinary surrounding login/navigation remains usable.
- No specialized comparison workflow or comparison transaction requirements.
- No new external blacklist provider, mandatory proxy/firewall, new enterprise policy service, general memory-poisoning framework, exhaustive abuse audit, or permanent account-login test infrastructure.
