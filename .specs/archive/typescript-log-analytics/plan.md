# Unify Pi JSONL analytics in TypeScript

## Objective

Replace Pi's Python JSONL analytics with one in-process TypeScript DuckDB system that serves every active reader of the registered analytics sources, preserves append-only evidence, and supports exact and conservative legacy correlation without exposing content-bearing fields through the generic read model.

## Completion Evidence

- Evidence: After `.specs/find-fails-diagnostic/plan.md` is complete, an execution-time inventory accounts for every active registered analytics writer, reader, source schema, append boundary, existing test, and Python contract as migrated, preserved domain-only, or excluded with reason. Separate focused tests then prove the resulting persistent DuckDB store refreshes explicit-schema structural projections incrementally and safely across close/reopen; correlation is exact, deterministic, provenance-marked unique inference, or unmatched; `/find-fails` and every inventoried reader use typed in-process APIs or one bounded Pi analytics tool with no Python process or replacement CLI; current log-reading skills document only that system; and the Python analytics implementation and environment are absent. One composition smoke test joins a representative session, turn, tool call, workflow, orchestration, and damage-control lifecycle without reading content-bearing fields.
- Fails when: Any active Pi JSONL analytics command, tool, skill, or current operator documentation invokes or recommends Python, `uv`, or a standalone replacement CLI; `/find-fails` behavior regresses; a generic table persists messages, transcript payloads, arbitrary `data`, evidence, reasons, command arguments, local paths, filenames, or review narratives; historical JSONL is rewritten; ambiguous timestamp proximity is accepted as correlation; inferred correlation authorizes a decision; correlation context leaks across parallel work or a writer emits stale inherited context after its owning scope settles; append failures break the primary operation; background-terminal output is ingested; retired prompt-routing or expertise/memory systems are revived; or competing generic and domain-specific DuckDB lifecycle/refresh authorities remain.

## Boundaries

- In scope: `pi/lib/` shared correlation context, compact identifiers, structural source registry, persistent incremental DuckDB lifecycle/refresh, correlation edges, and typed analytics APIs; active correlation-producing writers in metrics, workflow telemetry, orchestration/subagent telemetry, workflow friction, damage-control/permissions, usage operations, and background-terminal lifecycle metadata; `/find-fails` migration from its completed dedicated store; all active Pi JSONL analytics readers; one bounded in-process Pi analytics tool for skill-driven queries; focused tests; Pi package metadata; current Pi log-reading skills, observability contract, and directly affected current documentation; removal of `pi/analytics/` Python code and environment after parity.
- Out of scope: Rewriting authoritative historical JSONL; ingesting background-terminal stdout/stderr or generic raw session/transcript content; enabling transcripts; reviving or migrating retired `pi/prompt-routing/` or expertise/memory logs; changing task or goal persistence into telemetry stores; a standalone TypeScript CLI; a dedicated log-health command/dashboard; arbitrary model-visible SQL; cross-machine synchronization; alerts, shipping, or a new retention promise for authoritative logs.
- Preserve: JSONL as append-only authority and DuckDB as disposable local state; transcript redaction, permissions, spill, rotation, retention, and failure isolation; existing domain writers where they own locking, permissions, or queueing; metrics best-effort failure semantics; current IDs required by external/runtime contracts; `/find-fails` fingerprints, selection, decision safety, report semantics, bounded evidence retrieval, and active-turn authority from the prerequisite plan; current reader output semantics unless correlation makes previously unavailable structural facts explicit; unrelated local changes and generated/private runtime state.
- Assumptions: `.specs/find-fails-diagnostic/plan.md` has completed, added `@duckdb/node-api` to Pi package metadata, and proven it on supported Pi runtimes before this plan starts; active means a source or consumer is reached by current extension registration/import, callable command/tool behavior, discovered skill guidance, package script, or current operator documentation, while retired prompt-routing and expertise/memory remain inactive; compact IDs are interpreted with their runtime instance and need only practical uniqueness within local retained telemetry, not global uniqueness.
