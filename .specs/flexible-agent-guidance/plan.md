# Align agent guidance with simple, flexible enforcement

## Objective

Revise Pi's development guidance and routing policy so consequential invariants remain enforced, contextual choices remain flexible, and advisory or experimental routing machinery has an explicit evidence-backed retain, simplify, remove, or evidence-insufficient disposition instead of persisting as unexamined policy.

## Completion Evidence

- Evidence: Repository guidance consistently distinguishes values, safety boundaries, outcomes, necessary procedures, overridable defaults, heuristics, contextual judgment, and discoverable environment facts; broad determinism and fallback prohibitions are replaced by simpler invariant-focused language; root ownership changes only when consolidation demonstrably improves scanability without increasing permanent context; Python and TypeScript `SKILL.md` files become thin routing cards with detailed references loaded only when needed; testing and PowerShell retain their directly evidenced decision value; Python and TypeScript stop duplicating repository package policy or imposing unconfigured tooling; disputed rules are preserved and surfaced for operator decision rather than adjudicated through model-to-model comparison; safety-critical Git, credential, target, protocol, rollout, and incident controls remain normative; and a reproducible bounded audit records observed routing use, cost, duration, structural validation coverage, external interfaces, and evidence limits before assigning each advisory and experiment mechanism a retain, simplify, remove, or evidence-insufficient disposition, with focused checks passing for every changed contract.
- Fails when: A heuristic is still presented as an invariant, flexibility is used to weaken a safety boundary, an optional root-orientation edit grows, merely reformats, or loses an owner or repository constraint, a generic language skill restates lockfile/configuration truth or mandates package machinery absent from the active project, a disputed rule is silently removed or decided by matched agent output, testing loses seam or isolation guidance, PowerShell loses native-command or `ShouldProcess` guidance, routing code is deleted without checking active interfaces and available evidence, an experiment remains without a decision or retirement disposition, telemetry correlations are presented as causal quality evidence, or changed executable behavior fails focused validation.

## Boundaries

- In scope: `AGENTS.md`; `pi/AGENTS.md`; the development-philosophy, skills-engineer, orchestration, analysis-workflow, code-review, testing, Python, and TypeScript skill guidance named by T2; the existing Obsidian failure-category research note and index if its title or link changes; bounded read-only analysis of canonical orchestration metrics; routing-experiment evidence and documentation; and, only when the audit supports it, advisory routing, effort-default, non-experiment telemetry, documentation, and focused test code.
- Out of scope: New policy engines, schedulers, routing experiments, modification or removal of `codex-routing-outcomes-v1`, new telemetry fields, analytics persistence, general prompt-router redesign, model-provider additions, unrelated skills, broad framework-reference rewrites, formatting-only cleanup, live infrastructure behavior, damage-control weakening, command manifests, generated instruction files, cross-client quality or damage-control parity machinery, path-normalization unification, and any change to `install.conf.yaml`, `wsl/install.conf.yaml`, or `test/test_config_patterns.py`.
- Preserve: Explicit user overrides; user-requested model selection; provider availability and compatibility checks; simple `modelSize` resolution where it remains an active interface; repository and module ownership; client implementation independence; the existing passing WSL manifest parity contract; testing seam, isolation, real-boundary, and focused-falsification guidance; PowerShell native argument, exit-status, scalar-pipeline, version, and `ShouldProcess` guidance; destructive-operation, secret, wrong-target, external-protocol, live-rollout, and incident-recovery boundaries; unrelated working-tree changes; and current behavior unless this plan names it for evidence-backed simplification.
- Assumptions: Canonical local orchestration metrics can establish observed use, classifications, cost, duration, status, and structural-validation availability but may not establish causal task quality. Missing quality evidence is reported as insufficient rather than equivalence. An existing experiment that cannot answer its stated decision is preserved for later operator reconsideration with its evidence gap documented; this plan does not redesign, replace, extend, or remove that experiment. For skill cleanup, direct source, ownership, duplication, and accuracy evidence governs clear cases; any rule whose distinct value remains uncertain is left unchanged and presented to the operator as it is encountered, with the exact text, keep/clean consequences, and recommendation before further mutation. Matched agent comparisons are not acceptance evidence. `/do-it` must create and own the implementation worktree before changing files, then archive, commit, merge with `--no-ff`, verify merged HEAD, and remove only its owned worktree and branch.
