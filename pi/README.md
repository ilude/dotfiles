# Pi Profiles

Interactive zsh and PowerShell expose `pi` as the sole public launcher and invoke the internal profile helper directly. New and resumed default-profile sessions record that active profile once as a metadata-only `session-profile` custom entry in the session JSONL; it is excluded from model context.

- Bare `pi` uses `pi/profiles/default/` with startup preflight.
- `pi --profile legacy` uses `pi/profiles/legacy/`, which contains the previous customized Pi setup and its local runtime state.
- `pi --profile <name> --resume <session-id-or-path>` resumes a saved session in that profile.
- Other named profiles use `~/.pi/profiles/<name>/`.
- `-p <name>` remains a profile-selection alias. Use `--print` for Pi print mode, or pass Pi's short `-p` after `--`.

## Default installation and acceptance

Normal Bash and PowerShell installation calls the same bounded stage,
`bash scripts/pi-default-setup`, after installing the global Pi runtime. It uses
frozen default-profile installs, links the matching runtime, checks runtime
loading, and sets the native `~/.pi/agent` alias. Historical legacy dependencies
are not installed or tested during normal setup or default CI.

`node scripts/pi-setup-smoke.mjs --root <checkout>` then checks the actual Pi CLI
in offline RPC mode. Native fallback is tested without `PI_CODING_AGENT_DIR`;
the internal wrapper must load the same default configuration and runtime model
definition. The probe sends no model prompt and disables discovered resources
and network activity. Other runtime checks cover the safety bootstrap separately.
Without credentials Pi may select a fallback model; configured-default selection
is checked when that model is available. Installation reports authentication as
unverified. Use `/login` in default and a real request to verify subscription
access. Existing Pi processes and loaded shell functions still need the relevant
restart or reload after configuration changes.

Agent-directory links are replaced without deleting their destination contents.
If the native path is a physical directory, its archive must succeed before it
is removed. Windows uses native junction operations with paths passed as data.

## Default profile on Pi 1.2.0

Use `/login` in the actual default profile and choose native `openai` with the

legacy route; its login is not native OpenAI authentication. Do not copy or
relabel credentials between them. Default keeps native OpenAI model login unchanged;
quota reporting uses Pi's separate `openai-codex` OAuth login and renewal. Default startup remains
`openai/gpt-6.1-sol` at low thinking, and `/sol` remains pinned to Sol 6.1.
Native OpenAI classifiers use the separate Decisions API, not subscription chat.

Pi 1.2.0 runs `before_agent_start` for both user and custom-triggered turns.
First-user Herdr naming checks `messageType` before reading `prompt` or consuming

continue applying to both turn kinds. Use `/reload` only with no active or
retained subagents, or restart Pi, to load extension changes. Existing sessions
retain their selected model until switched or restarted. Offline focused checks
cover event behavior and native model selection; interactive Herdr UX remains a
separate, non-blocking verification limit.

## Default profile implementation ownership

Default customization uses native `getAgentDir()` for active-profile paths and `profiles/default/lib/profile.ts` for profile labels. Model catalog requests, cache persistence, reconciliation and compatibility conversion live under `profiles/default/lib/models/`; the refresh extension coordinates command output and settings updates. Context analysis and report formatting live in `lib/context-analysis.ts` and `lib/context-report.ts`, with Pi state collection in the command extension.

`profiles/default/lib/path-identity.ts` separates repository IDs from filesystem paths. `repositoryId(root, repository)` creates root-relative IDs with `/` separators (`.` for the root) using the absolute root's Windows or POSIX semantics. `normalizeRepositoryId()` accepts native separator spelling at Windows tool boundaries without rewriting POSIX literal backslashes, case, or path segments. `/commit` uses these IDs for inventory, publication, ignore decisions, and result labels, while retaining native absolute paths for filesystem/Git operations. `samePlatformPath()` remains the separate absolute-path comparison helper. Shell path conversion stays explicit at the owning Git Bash/WSL boundary; repository IDs are not shell arguments or a substitute for containment checks.

`extensions/profile-reload.ts` owns reload polling independently of the footer. It publishes state and answers snapshot requests over Pi's shared event bus; the footer and `/clear` never rely on shared imported singleton identity. Each extension gets a separate loader. The monitor baseline belongs to the evaluated owner factory: same-cwd session replacements that reuse cached factories retain it, while actual resource reload reevaluates source and establishes a new baseline. Timers and subscriptions are session-owned and cleaned up on shutdown. `lib/model-runtime.ts` shares profile-local runtime creation configuration for web screening and commit review, but each feature retains its own runtime lifetime, cancellation and permissions. These modules belong to the default profile, not a cross-profile framework.

## Default profile native tool discovery and composition

Native search discovers permitted inactive deferred tools; it does not discover inactive direct tools. Use the native query interface, not the retired custom list, parameter-inclusion, or activation switches. Command activation such as `/yt` remains additive and does not bypass command permissions.

Approved work tools return typed `structuredContent` for scripts while retaining conversational content and renderer details. Web results remain screened and bounded, browser results remain sanitized, and vault results retain their projections. Jev returns an explicit success/error distinction; other thrown failures remain failures. A communication or ingestion receipt means submitted or accepted, not recipient or job completion.

Only the orchestrator and Team Lead receive codemode. Ordinary roles retain permitted native search without codemode. Lifecycle tools (`subagent`, `subagent_control`, `commit_run`, and child `subagent_parent`) remain model-only and cannot be called from scripts. Native classifier helpers remain native; the Jev client is unchanged.

Nested tool calls retain permission and Damage Control hooks. Scoped instructions discovered by a nested operation reach the outer persisted result without removing structured data. Native script store, restoration, branching, cancellation, and side-effect semantics apply: store writes from failed scripts are discarded, but completed external side effects are not rolled back. Do not infer success from an inner error value or a submitted receipt. The bounded offline runtime check is `node scripts/native-composition-smoke.mjs` from `profiles/default/`; it runs installed Pi's actual native search and QuickJS executor with nested-tool fixtures, without a provider or live service.

## Default profile safety port

Damage Control's [governing design requirement](profiles/default/docs/damage-control-port.md#design-purpose) is to prevent meaningful unrecoverable harm, not to block every suspicious-looking action. The [risk and proportionality review](../.specs/archive/damage-control-risk-alignment-and-preapproval/damage-control-risk-review.md) records the policy, context, watchdog, and script-reuse findings behind the current implementation.

Explorer receives guarded Bash and PowerShell for local and live evidence investigation, without native edit/write tools. Its frozen role-bound inspection policy blocks intentional mutation even when temporary or recoverable, reviews unfamiliar complete calls with an inspection-specific tool-free judge, and denies uncertainty or review failure without a mutation override. `/dc off`, default mode, reload, user authorization, and normal script preapproval cannot weaken it. Existing protected reads still apply. Explicit operator `!`/`!!` input retains its exemption. This is best effort, not an OS sandbox or zero-side-effect guarantee; incidental client-cache updates and access logs are compatible with observation. New children receive the tools after the normal settled-only reload or a fresh session, not by retrofitting active children. See [Explorer inspection](profiles/default/docs/damage-control-setup.md#explorer-inspection).

Damage Control is enabled for normal default-profile `pi` launches. Deterministic routine cases run quietly while consequential contextual cases use bounded Luna judgment. `/dc scan` reviews project-owned scripts through read-only subagents without executing them; source-hash and optional argv/helper-bound approvals are shared across Git worktrees and skip only matching script-body analysis. Eligible prompts can allow the current call while reviewing it for future reuse. An exact failed-call watchdog blocks attempt thirteen and keeps the run stopped until new direct operator input; before it trips, unrelated calls and successful repetitions reset or avoid the streak. `/dc on`, `/dc off`, `/dc scan`, and `/dc mode default|noshell` are supported; there is no status command. The explicit `pi --dc-recovery` path, `/commit` exemption, direct operator shell exemption, and legacy profile remain unchanged. See [setup and behavior](profiles/default/docs/damage-control-setup.md).

## Default profile footer

The operator footer shows repository, model, context, and provider usage. `[reload]` indicates changed resource files since startup or reload. Every 15 seconds, an asynchronous, single-flight scan checks first-party profile code and resources, trusted project resources, literal configured paths, first-party loaded command/tool provenance, and the shared Onclave adapter inputs used by Pi. Themes and third-party pnpm code are excluded, even when Pi reports a loaded source path. It compares file contents, so metadata-only touches do not request a reload and reverting content clears the indicator. In settings files, formatting and key order plus immediate model/provider/thinking selections and the last-seen changelog version are ignored; resource configuration and model catalog scope still count. It excludes credentials, sessions, generated model catalogs, usage ledgers, and files beneath a discovered skill other than its reloadable `SKILL.md` definition. Monitoring failures display `[reload check failed]`; package glob additions and arbitrary imported dependencies are not comprehensively discovered. `/clear` requests a current scan before deciding whether to reload; use `/reload` directly to load changes and reset the baseline.

## Default profile usage and context reports

Subscription usage is shown in the transcript on fresh Pi startup and after `/new` or `/clear`. Starting with an existing conversation, including `/branch`, refreshes the footer without appending another usage report. `/usage` fetches live quota percentages, reset times, banked resets and their expirations, and credit balances, retaining local OpenAI prompt cache-read statistics, Bedrock estimates, and a link to [ChatGPT usage settings](https://chatgpt.com/settings/usage).

Default keeps native `openai` subscription login in Pi for Sol 6.1 and other model requests. Live quota reporting resolves the active profile's `openai-codex` OAuth credential through Pi's model registry. Pi owns storage and automatic renewal, including its cross-process refresh lock. No Codex CLI, CLI credential file, subprocess, token copying, or machine-specific credential path is used. These remain separate OAuth grants: the native model credential was rejected by the quota endpoint, while the Pi `openai-codex` credential returned quota data.

On a machine without quota authorization, click the underlined `login needed` label in Pi's fullscreen footer, or run `/usage login` in either terminal mode. This uses Pi's built-in Codex flow and refreshes the footer immediately afterward. It skips the method menu: local Windows/macOS and graphical Linux sessions use browser login; SSH/Mosh sessions and headless Linux use device-code login. Detection uses the session environment, not a guarantee that a working default browser is configured; `/login openai-codex` still lets you choose manually. Regular terminal mode leaves mouse handling to the terminal, so use the command there. The existing `/login openai-codex`, then `/usage` path remains available, including device-code login for remote/headless machines. Existing Pi quota credentials are reused without a new sign-in; login does not switch the selected model or replace native `openai` credentials. A new machine/profile needs its own authorization, not credentials committed or copied through dotfiles. Cancellation stops the usage reader while Pi finishes any already-started token rotation and persists its result.

The footer shows real used percentages for reported quota windows, with pacing colors. Missing windows are omitted, not invented as `0%`; a weekly-only plan displays `codex: wk 2%` when that is the reported usage. Quota requests are shared between the footer and report, cached for five minutes, and polled only with a UI. Failures mark the last good footer value `stale` with the failure category, or show `login needed`, `auth renewal failed`, `authorization rejected`, `network error`, `request timed out`, or `API error` when no quota is cached. `/usage` gives the corresponding retry or Pi login instruction without persisting provider token responses; cache-read share is never substituted for quota. An immediate reload after `/clear` completes a pending report without duplicating a completed one. Reports are display-only custom entries, never model context.

Cache statistics cover the last 100 observed native OpenAI assistant responses in the active profile, across sessions. Cache-read share is `cacheRead / (input + cacheRead)` over responses with both counts available. Only model names and those counts are appended to the existing gitignored `codex-cache.jsonl`; reads are bounded to its last 128 KiB. The log is append-only and may be deleted to reset history. Its filename and recorded history are preserved. Legacy history is not imported. No request-shape diagnostics, `/cache-doctor`, orchestration telemetry, or hidden session datetime injection is included.

Footer line 2 shows live output throughput, first-token latency, token count and streaming duration alongside scheduler and Bedrock status. Every output delta contributes to the character-based estimate, but streaming presentation is coalesced to a 500 ms cadence, with prompt updates on the first token and at message completion. Live estimates use `~`; final throughput uses provider output counts and excludes tool execution and first-token waiting. Latency is measured from Pi's assistant-message start to its first nonempty output delta (including thinking/tool arguments), not from an independently observed HTTP send. Final values remain visible and restore on reload/resume; new sessions clear them. At narrow widths scheduler then timing take priority, with Bedrock shown at the right when space permits.

`/context` shows estimated prompt components, tool schemas, context files, skills, messages, thinking, tool results, summaries, cache usage and session spend. It uses Pi's compaction-aware active entries and separates component estimates from provider-backed context totals. These are not exact tokenizer measurements or an inspection of the final provider payload. `/context widget` shows a snapshot above the editor; `/context hide` and `/context clear` remove it without clearing the conversation.

Refreshed non-Bedrock catalogs are restored from the gitignored `model-cache/refresh-models/` directory, and changed catalogs or curated scope trigger a resource reload.

## Default profile scheduling

The agent-facing `schedule` tool provides one-shot `create_at`, `list`, and `cancel` actions for user-requested reminders or tasks that genuinely depend on a known future wall-clock time. It must not be used to continue implementation, advance a plan, extend a turn, wait for normal tool or agent work, or compensate for stopping early. Before creating a job, the agent lists existing jobs and avoids duplicate or overlapping reminders. Use a positive duration (`30s`, `15m`, `2h`, `1d`) or a future ISO timestamp; timestamps without an offset use local time. There are no scheduling slash commands, recurring jobs, persistence, metrics, or extra dependencies. To change a schedule, cancel it and create another.

Schedules live only in the current Pi process. They survive `/new`, `/resume`, `/fork`, and `/reload` within that process, delivering into whichever conversation is active, not necessarily the originating project. `/branch` opens a separate process with no inherited timers. The child's model context identifies the branch boundary and leaves inherited monitoring/reminders with the parent unless the user asks to continue them in the child; an empty child schedule list is expected, not work to restore. This context is reconstructed from persisted branch metadata after reload/resume and compaction, not stored as a one-time chat instruction. Scheduling remains available for the child's own work. At the due time, Pi receives a follow-up prompt: idle agents start a turn; busy agents finish their current work first. Closing Pi discards all schedules, and timers do not keep a noninteractive process alive. Prompts due during session replacement are handed off after rebinding. Cancelling works only before handoff; prompts already in Pi's queue cannot be recalled by this tool.

The footer shows only the next injection time (`sched@ 9:00am`, local time), clearing when none remains. It does not show pending states or errors. Synchronous handoff failures remain inspectable through `list`, with no automatic retries or injected error prompts; cancel and reschedule them. Limits remain 64 outstanding schedules and 4,000 characters per prompt; slash-command prompts are rejected. Use `/reload` to activate the tool.

## Default profile log analytics

The default profile provides deferred `log_analytics` for existing sessions and usage records. Activate it through `tool_search` with `session analytics`. Choose `catalog` for schemas, cheap metadata-only `sessions`, DuckDB-free bounded `search`, bounded exact `follow_up`, `session_lineage` for recorded subagent ancestors/descendants, or one native SELECT `query`. New subagents automatically persist their role, immediate parent session ID, and root session ID without launch parameters or plan tracking. Search `tool_search` for `subagent session lineage` to discover the lookup; historical sessions without lineage stay unclassified and recorded relationships do not establish live status. Searches default to the active registered profile; select `profiles: ["legacy"]` or `["default", "legacy"]` explicitly. Use normalized `cwd` for one checkout or `repository` to include that Git checkout and its linked worktrees, and retain event-time intervals across continuation. Exact session references reduce staging. Event-time filters use record timestamps, so old resumed sessions are not missed.

Use `search` for targeted lookup and last-week recorded tool failures: freeze `[since,until)`, filter `messageRoles: ["toolResult"]` and `isError: true`, page with the unchanged `nextCursor`, then follow relevant occurrences. Use `filters.subagentBlocking` to retrieve structured foreground/background subagent decisions, recorded or role-derived blocking reasons, and the active subagent extension version without DuckDB. Restrict a later review to one runtime with `filters.subagentExtensionVersion`. Use exhaustive pages for a three-month traversal and disclose exclusions and gaps. Use `query` with `execution: "large"` for deliberate broad joins/aggregates; standard SQL is the cheap in-memory path. Search reports selected/examined coverage and cursor boundaries; SQL reports phase/input/resource costs. Recorded error flags are evidence, not automatic product defects.

Tool rows show operation and scope, compact matches or query tables, continuation/completion, truncation, and exclusions. Expand tool output (normally `Ctrl+O`) for returned bounded values, full SQL/parameters, occurrence coordinates, diagnostics, and large-mode resource costs. Expansion does not fetch more data; model-facing JSON is unchanged.

Existing JSONL remains authoritative. Search/header discovery do not load DuckDB. Damage Control judge calls may append bounded, redacted versioned diagnostics as custom session entries; these are excluded from model context and are not indexed by analytics. Standard SQL retains invocation-local in-memory staging; large SQL uses a bounded reader and invocation-owned disk database. Both retain their configured deadline plus 2 GB/two-thread limits and bounded spill under the invocation-owned directory. DuckDB's native `max_temp_directory_size` remains configured at the 8 GiB owned-disk budget, and explicit recursive owned-disk checks run at large-staging batch/checkpoint boundaries and query completion. There is no recurring directory-walk timer, so the reported peak and 8 GiB budget are boundary observations rather than a continuously enforced hard cap. Owned temporary content is cleaned after success, error, or cancellation, and SELECT remains read-only. The disposable metadata cache contains only validated markers, headers, and observed ranges, never transcript content. No telemetry, persistent transcript index, history import, or legacy report commands is added. See the [skill and query reference](profiles/default/skills/pi-log-analytics/SKILL.md) for recipes, source support, coverage, limits, installation, and offline checks. Use `/reload` or a fresh `pi` session after installation; analytics starts deferred.

## Default profile updates

`/update` installs the latest stable Pi with pnpm, refreshes the default runtime links, and makes one pass over Pi sessions across the connected Herdr server. Each eligible process exits gracefully and resumes its exact saved conversation, cwd, and profile; the invoking session goes last after reporting peer results. Supervised sessions retain their pane. Existing sessions without that host migrate to a replacement pane in the same tab. Existing tab/pane labels and naming ownership survive. Outside Herdr, only the invoking session is considered.

Busy sessions, active prompts, queued messages, unsent editor text, active or retained subagents, and sessions without a saved conversation are skipped. There is no background retry or Herdr update. Only cooperative sessions using the same default profile are restarted. Existing sessions load cooperation with `/reload`; sessions that have not loaded it and other profiles are skipped. Installation or runtime-link failure prevents all restarts.

The Bash/PowerShell default launchers and ordinary Herdr bootstrap now keep a lightweight Node host around the real Pi CLI so it can replace the child without closing its terminal. Existing Herdr sessions can use `/reload` to load `/update` without exiting. Their first update opens a waiting replacement in the same tab, then gracefully shuts down the original. The replacement waits for the old process to exit before opening its conversation, retires any leftover old pane, and confirms the resumed session/version. Subsequent updates keep that new pane. Outside Herdr, direct native executable launches without the host still require relaunching through bare `pi`. Recovery mode and legacy are unchanged. Automated tests use fake Pi children and mocked installers; actual package updates and attached-client restart behavior need a deliberate live run.

## Local-first Onclave backfill

Default Pi owns the supported Onclave vault API path. A native per-user scheduler may run the short-lived TypeScript backfill worker from `tools/onclave-backfill`; it scans complete local transcript caches first and exits without network or credential access when none are ready. The worker fails fast per run, catches up at login, and deletes a cache only after a verified upload. Configuration is stored at `~/.dotfiles/yt/onclave-backfill.json` and contains the endpoint and key path, never key contents.

Installers warn and continue when Node, configuration, or the native scheduler is unavailable. They do not fall back to cron or the retired Claude hooks. Use the worker's `--status`, `--disable`, and `--uninstall` entry points for operations; uninstall removes only definitions carrying the dotfiles ownership marker.

The native path `~/.pi/agent` points to default, so Pi also uses default when launched without the interactive shell function. Legacy is historical reference and is selected only explicitly.
