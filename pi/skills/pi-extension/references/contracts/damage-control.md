# Damage Control

- Ownership: Pi owns its damage-control policy, parser, enforcement, decisions, and telemetry. Retired cross-client parity plans and shared-policy proposals are not current authority.
- Authorization: a direct request authorizes its named target and mutation, but does not erase executable safety controls. Do not ask for a second conversational approval when the tool-level damage-control boundary already governs the action.
- Outcomes: covered calls resolve to allow, ask, or block. Hard blocks have no approval path. Ask-tier calls use the runtime confirmation boundary; denial, Escape, or unavailable UI fails closed.
- Policy health: missing, malformed, invalid, or unsupported policy fails closed for covered tools. Never silently fall back to an allow policy.
- Scope: enforcement occurs before registered covered Pi tools execute. It does not automatically govern unrelated external harnesses or processes that bypass Pi tool hooks.
- Shell modes: current modes are `default` and `noshell`. `noshell` blocks Bash and PowerShell. Retired whitelist and plan-grant modes must not be restored implicitly.
- Bypass: `/damage-control off` and `/dc off` enable a non-persisted, session-local bypass for ordinary local ask-tier rm, Docker, and Git operations. `/damage-control on` and `/dc on` clear the bypass status and restore normal asks. `session_start` resets the bypass, including the `/clear` new-session lifecycle, and process exit discards it.
- Bypass eligibility is enforced at the centralized dangerous-command and protected-path seams from one invocation-wide parsed-effect aggregate. Hard blocks, sequence protections, ambiguous or dynamic shell targets, remote/cloud/live infrastructure actions, remote Git mutation, executable Git transport overrides, Docker volume deletion, and exfiltration remain protected. A `.env` path is bypassable only after canonical containment under the effective Git repository root succeeds; repository discovery failure retains protection except for the bounded safe-destination `git clone` case.
- Paths and commands: parse the complete Bash or PowerShell invocation before deciding a bypass, and analyze supported inline or canonical repository-contained Python, JavaScript, and TypeScript sources within the bounded source and recursion limits. Canonicalize targets before decisions. Apply tool-, platform-, path-, semantic Git-, AST-, sequence-, taint-, and secret-output controls together; one narrow allow does not suppress other matching rules.
- Deletion: auto-allow ask-tier deletion only when every statically proven target stays inside the session cwd or an approved scratch root. Dynamic targets, traversal, protected floors, symlink prefixes, parse failure, and remote payloads retain confirmation or blocking.
- Repetition: stop repeated equivalent failures, blocks, or successful no-op calls with the circuit breaker. Before aborting the run, publish the bounded redacted stop reason into model/session context so the next turn can change approach; the TUI warning and generic aborted tool result are insufficient. Reset on direct user input or settlement, not on automatic continuation.
- Audit: record bounded, redacted decisions and rule-load failures. Debug logging is opt-in. Shadow judging is asynchronous and non-authoritative by default. An explicitly configured Luna reviewer may authoritatively auto-allow only a deterministic, known, low-risk ask after all seams pass, with strict JSON, fixed high effort, no tools, and no provider/model fallback; every failure retains the original prompt.
- Footer: normal damage-control status is absent from the operator footer. During bypass, the only damage-control footer text is `damage-control: bypassed`, rendered in the error color.
- Live failure: the first failed live mutation stops broader rollout. Diagnose and recover that boundary before continuing.
