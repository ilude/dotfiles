# Interactive Workflow Lifecycle

- Ownership: `/plan-it`, `/do-it`, and `/goal` share one deterministic Git worktree lifecycle. Each invocation creates or resumes exactly one owned branch/worktree beneath repository-root `.worktrees/`; the ownership record is durable and modifications are confined to that worktree. `/plan-it` may create its isolated worktree from the primary branch while the primary worktree has unrelated tracked or untracked changes and must leave those changes untouched. New `/do-it` and `/goal` work still require a clean primary worktree.
- Planning: `/plan-it` creates one canonical `.specs/{slug}/plan.md` in the owned worktree. Record draft and risk, perform one correctness review, apply supported findings, run a final subtractive overengineering/gold-plating/churn gate, resolve genuine blockers with the operator, and call ready only after deterministic plan validation passes. There is no duplicate review path.
- Plan contract: include objective, observable completion evidence, mutation boundaries, executable tasks, real dependencies, validation, retention/archive instructions, and current status. Do not invent scheduler state or duplicate ledgers.
- Execution: when `/do-it` receives a canonical plan, that plan is the sole execution ledger. Resume from the first unchecked dependency-ready task and update it after each verified result. Do not mirror its checklist into durable tasks unless separately requested. Raw `/do-it` is valid only after ownership is established.
- Raw work: bounded direct work needs no plan or durable task. Create one root task only when raw work is likely to span compaction, delegation, or delayed continuation.
- Validation: run the smallest checks that directly exercise the completion evidence. A reported command, stale result, or model summary does not substitute for observed validation.
- Closeout: after all tasks and validation pass, archive the entire spec directory on the workflow branch, commit it, merge with `--no-ff` into the primary worktree branch, verify merged HEAD, mark ownership complete, and remove only the owned worktree and branch. A dirty primary blocks closeout; unmerged, conflict, failed-merge, or failed-cleanup states preserve the recovery worktree. Reject incomplete plans, unsafe paths, and collisions.
- Compatibility: legacy lifecycle stages may be read for restoration, but removed review/adjudication stages are not current workflow gates. The obsolete review-only command and artifact tool are not registered or discoverable.
