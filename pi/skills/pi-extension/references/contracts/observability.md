# Observability, Transcripts, and Usage

- Separation: content-bearing transcripts and metadata-only operational metrics are different trust boundaries. Never treat one as interchangeable with the other.
- Analytics authority: active Pi JSONL readers use typed in-process TypeScript APIs or the bounded `log_analytics` tool. `catalog` exposes stable source IDs and same-named DuckDB views; `query` accepts explicit source IDs, documented DuckDB SQL, scalar parameters, and row/byte bounds. Selected views preserve each complete original JSON record as `record` and expose `_source_file`, `_record_key`, and `_timestamp` plus optional typed convenience columns. SQL may use ordinary DuckDB date predicates, CTEs, and JSON functions, but prepared views are the only filesystem boundary. Results are iterated incrementally and report truncation. Canonical JSONL remains append-only authority; DuckDB is one invocation-local in-memory engine with no persistent analytics projection, refresh state, WAL, or shared connection cache.
- Correlation: shared structural context uses runtime-scoped identifiers for session, turn, trace, interaction, workflow episode, orchestration, run, task, goal, tool call, and operation. Precedence is exact, deterministic, unique_inferred, then unmatched. Timestamp proximity alone is not a join. Unique inferred edges are opt-in and provenance-marked; they are never decision authority. Decision APIs accept only authoritative exact or deterministic results.
- Context isolation: inherited correlation is immutable and scope-bound. Child or detached work receives an explicit serialized envelope or emits without inherited context; settlement invalidates captured context so post-settlement writes cannot publish stale inherited fields. Append or refresh failures are observational gaps and do not break the primary operation.
- Transcripts: tracing is off by default and enabled only in per-user runtime settings. It may capture provider payloads, visible assistant content and thinking, tool inputs/results, errors, and selected headers. Hidden provider reasoning is never captured.
- Transcript safety: clone and redact before persistence, restrict local permissions, reject configured cloud-sync paths, spill oversized redacted fields to bounded companion files, and correlate records without emitting per-token events.
- Transcript retention: apply configured retention at session start and support explicit purge. A bare `/transcript-purge` age is measured in days; explicit `ms`, `s`, `m`, `h`, and `d` suffixes remain supported. Purge only the inspected trace and spill boundary.
- Metrics: metrics are best-effort, append-only operational metadata. Producers must not include prompts, tool arguments, terminal output, response content, secrets, or unbounded free text.
- Failure: disabled or failed observability must not break the primary tool, workflow, or session operation. Record gaps rather than inventing missing evidence.
- Interpretation: metrics and traces are observational. They do not by themselves prove correctness, completion, quality, causality, or savings. Missing pricing is unknown cost, not zero cost.
- Tool-failure authority: `/find-fails` is a TypeScript-only bounded diagnostic. `pi/lib/tool-failure-classifier.ts` and `pi/lib/tool-failure-decisions.ts` own deterministic joins, fingerprints, timestamp windows, custom-extension filtering, thresholds, stable selection of at most three candidates, ledger precedence, and append-only decisions. Session JSONL and the private decision JSONL remain authoritative evidence; failed-tool scanning uses the invocation-local analytics query only to read bounded session records and does not persist a scan copy or analytics database.
- Selection: restrict the pool to currently registered custom-extension tools before ranking or applying the three-candidate limit. Post-effective regressions and changed fingerprints precede internal defects, recent multi-session failures, repeated workflow blockers, and sufficiently evidenced unclassified failures. A candidate selects its newest valid-timestamp failure first, then distinct sessions, with session digest and coordinate token as deterministic tie-breakers; invalid or missing timestamps follow valid timestamps. Its reported last-seen value comes from the same ordering. Structural counts and model confidence never qualify a decision. Missing, malformed, future, stale, contradictory, or incomplete evidence remains unresolved. When nothing is selected, report scan, custom-tool, prior-decision, resolved, and below-eligibility counts instead of claiming that no findings exist.
- Decision safety: the narrow writer may append only an evidence-proven documented safety or authority rejection, accurate caller-contract rejection, deliberate cancellation, temporary external failure with a revisit date, or proven fix with typed evidence and an effective date. Its public evidence schema uses bounded `{ type, text }` objects with `commit`, `test`, `issue`, or `note` types and normalizes them to the compatible persisted `type:text` form. Reasons and evidence reject secrets, absolute private paths, control characters, and multiline content. Caller-contract decisions persist one validated ISO observation boundary; only failures and distinct sessions strictly after that boundary can reopen the same fingerprint. Appends use a cooperating lock, write one complete sanitized record, flush and fsync before success, and ignore or quarantine only an incomplete trailing record without rewriting valid prior records. The supported direct fix verifier is limited to `required:command`: the inspected failed envelope must be a Bash missing-command rejection, and the same selected finding must have a later successful Bash envelope with a nonempty `command`, inspected in the current diagnostic turn, whose result timestamp is strictly after a validated ISO `effectiveAfter` boundary. Prior date-only records remain readable but cannot prove a new fix; unsupported contracts, mismatched tools, pre-boundary or uninspected successes, counts, and free-form claims remain unresolved.
- Provider and inspection boundary: a diagnostic run starts exactly one normal active-session turn, not an isolated model call or shortlist transcript message. It discloses the provider boundary, exposes only bounded selected-coordinate transcript inspection (`tool_failure_inspect`) and the narrow decision writer (`tool_failure_decide`), denies protected, generated, private, and out-of-workspace paths before reading, and enforces per-call and per-turn item and byte limits. Inspection returns a structured call/result envelope with opaque correlation metadata; it recursively redacts secret-named fields and secret-like values, applies explicit field and collection truncation, and never exposes source paths or surrounding transcript content. The active model reads selected evidence itself. It cannot mutate repository files or delegate work. Agent end, cancellation, error, reload, and session transition settle the owned restriction by recomputing the desired tool set.
- Report boundary: every finding uses one human verdict from `Failing`, `Fixed`, `Expected`, `External`, or `Unresolved`, followed by `Last seen: M/D/YYYY h:mm:ss AM/PM` in local time and concise evidence. `Fixed`, `Expected`, and `External` require their direct proof. For a `required:command` finding, the prompt may expose only the opaque eligible fix-check token; using it does not expand the two-tool restriction or permit arbitrary replay or command execution. The report states once that no code changed and never exposes ledger terms or assumed future-scan behavior. It offers action only when action remains and does not invent options.
- Retention boundary: metrics currently have no built-in retention guarantee. Do not promise automatic deletion, permanent retention, or cross-machine synchronization without an explicit policy.
- Storage: generated sessions, histories, traces, metrics, workflow-friction records, caches, and indexes remain local runtime state and are not tracked repository source.
