# Provider and Model Lifecycle

- Credentials: provider credentials belong in Pi's local auth boundary or provider-scoped environment configuration. Do not embed credentials in model metadata, tracked settings, cached catalogs, telemetry, or tool output.
- Discovery: provider discovery produces candidate models. Visibility policy separately decides which models become selectable and may hide snapshots, previews, blocklisted IDs, unsupported families, or region-incompatible entries.
- Startup: perform provider/model initialization through the standard session-start wrapper. Preserve thrown startup failures unless the owning provider explicitly defines a bounded warning or partial-success path.
- Refresh: `/refresh-models` refreshes every supported configured provider, including AWS Bedrock model discovery through provider-scoped credentials. A multi-provider refresh may continue after one provider fails, but must report that partial failure. Refresh updates only the owning catalog/settings fields and preserves unrelated configuration. It rebuilds the exact `enabledModels` scope from filtered available models in Codex, Bedrock Mantle, OpenRouter, OpenCode, then remaining configured-provider order; it never copies unfiltered remote catalogs into that scope. Bedrock persists a complete sanitized AWS inventory (including runtime inference-profile metadata) without credentials or headers, and reloads internally only after a catalog change.
- Catalogs: cached discovery may restore models the installed Pi catalog does not yet know only where the provider owner explicitly supports that behavior. Bedrock Mantle consumes the persisted Runtime inventory to expose the newest logical Claude ID and its `us.*` Runtime target when Mantle lacks that family; visibility consumes the same inventory. Do not infer freshness, expiry, or compatibility guarantees absent an implemented rule.
- Bedrock boundaries: Bedrock Runtime and Bedrock Mantle are distinct routes with distinct regional catalogs and credential resolution. Request-scoped credentials override ambient Mantle credentials where supported.
- Routing: choose Mantle or Runtime before a request starts. Do not replay a failed request through a different endpoint. GPT uses the Mantle OpenAI Responses route; Claude uses Mantle Anthropic Messages when available and the configured Runtime inference profile otherwise.
- Model selection: verify model existence and the boolean result of `pi.setModel()` before reporting success. A refresh or visibility change must update the current runtime rather than claiming a restart-only result. Model and thinking selections remain session-scoped across reload; Pi owns explicit persistence of user-selected defaults.
- Request transforms: direct personality is an opt-in request transform for supported OpenAI GPT-5-family requests. It sets low verbosity only when the request has no explicit verbosity and does not alter discovery, credentials, or unsupported providers.
- Failure: preserve actionable provider errors and distinguish explicit misconfiguration from partial refresh failure. Never silently fall back to a different credential source or endpoint after a request begins.
