# Tool Visibility and Discovery

- Availability bias: keep general and specialized callable tools active so the model knows they exist. Defer only tools whose invocation is valid inside an owning workflow state, advanced modes with a compact active replacement and searchable explicit names, or control tools whose managed resource does not yet exist.
- State gates: commit execution, feature-memory recording, goal completion/progress, improvement decisions, plan archival, workflow-change tracking, and review-artifact writing remain inactive until their owning workflow activates them deterministically. `goal_progress` is active for a correlated unattended loop job or while an explicitly supplied foreground plan awaits reviewed materialization; `goal_complete` is active for either foreground or unattended goal state. `plan_archive` is active only while `/do-it` executes a canonical plan and deactivates after a successful archive.
- Advanced subagents: for ordinary roots, keep common single and parallel execution on `subagent`. Register `subagent_chain`, `subagent_continue`, `subagent_fanout`, and `subagent_workflow`, but deactivate them at session start. `tool_search` activates them on demand. Preserve legacy advanced arguments on `subagent` for resumed sessions without advertising those branches in its provider schema.
- Role gates: a leaf or depth-two child cannot activate or invoke delegation or workflow tools. A coordinator may use common `subagent` execution to start leaves; only a root may start a coordinator or workflow.
- Fable restriction: when the exact primary model is `amazon-bedrock/us.anthropic.claude-fable-5`, expose `subagent`, `subagent_chain`, `subagent_fanout`, `subagent_workflow`, `task`, and `ask_user` directly. Keep `tool_search` and `subagent_continue` unavailable. Let the existing owner expose `goal_progress` during active goal planning, `plan_progress` only during an active `/plan-it` lifecycle, and `plan_archive` only during an active canonical `/do-it` plan. Tool-owner changes made while Fable is selected remain current when the restriction is removed.
- Search behavior: keep `tool_search` active as a fallback for ordinary roots. A non-empty query activates all matching inactive tools by default; list mode never activates tools.
- Catalog: `tool_search` guidance names deferred chain, continuation, read-only fan-out, and typed workflow capabilities so hidden schemas do not make them undiscoverable.
- Telemetry: record metadata-only toolset exposure, hashed search decisions, activation results, and tool use. Do not record raw queries, arguments, descriptions, or output.
- Review boundary: telemetry supports later policy review but does not change activation policy automatically.
