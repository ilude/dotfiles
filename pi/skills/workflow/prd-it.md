# Draft or Refine a PRD

Load and follow `pi/skills/prd/SKILL.md` as the canonical PRD contract. Load `planning` when writing or repairing normative requirements and acceptance criteria. Do not duplicate either skill's detailed guidance in this wrapper.

Treat `$ARGUMENTS` as an explicit request to draft a PRD from an idea, refine the PRD at a supplied path, or review and revise supplied PRD content. If `$ARGUMENTS` is empty, ask what product or workflow idea the PRD should address.

Use the artifact path, minimal shape, clarification boundary, and optional handoff behavior defined by `prd`. Report the resulting path when an artifact is written.
