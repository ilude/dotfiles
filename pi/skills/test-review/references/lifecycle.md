# Root lifecycle and evidence contract

This reference is for the root only. The `test-reviewer` must not receive it as a skill or be asked to operate the checkpoint.

## Modes and state

Modes are `baseline`, `diff`, `path`, `deep-performance`, and `smells`. Explicit mode wins. Unqualified selection is: missing baseline -> start; active -> resume; uncertain -> refresh affected or all when unbounded; closed with changed inputs -> diff-first; unchanged closed -> report status and gaps. Limited modes state exact scope and never claim baseline completion. A closed-with-gaps run does not silently retry unchanged blocked work.

Mode precedence is an input rule: explicit mode and repository/path scope win first; otherwise reconcile identity, revision, inventory, and dependencies before applying the table. A command is admitted only after a manifest entry records owning cwd, exact arguments, runner/version, source/discovery reference, selected scope, finite timeout, cleanup, and authorization class. Unclear, external, destructive, live, or unbounded targets remain blocked.

State lives under the selected repository's Git common directory in `test-review/<baseline-name>/state.json` and `report.md`. The baseline name matches `[A-Za-z0-9][A-Za-z0-9._-]{0,63}` and cannot contain a separator, `..`, or an absolute path. State records schema version, baseline/repository/scope identity, root owner identity, lifecycle status, starting and final commits, inventory units, dependencies, reviewed commits/statuses, evidence references and bounded excerpts, measurements, findings/dispositions, commands, gaps, carry-forward comparisons, and reconciliation. Do not persist duplicate aggregate summaries.

Before writing, select one matching baseline by repository/scope identity; ask when multiple matches remain. Explicit `baseline` resumes active work or reopens requested gaps; a full refresh requires an explicit request. Dirty limited-mode work produces a separate limited report and cannot advance committed baseline state.

The private helper creates only a canonical-contained baseline directory and initial state, or performs a locked read-modify-write. It validates owner, repository/scope identity, and schema before mutation. It uses `proper-lockfile.lock(path, { realpath: false, retries: 0 })` with consistent `stale` and `update` settings, releases in `finally`, serializes before replacing, creates a uniquely named sibling temp file with exclusive creation, and atomically replaces the state on the same filesystem. Lock recovery never transfers logical ownership. Malformed, foreign, stale-owner, or uncertain state fails explicitly. The immutable `ownerId` identifies the logical baseline owner, not a disposable child or process. Store its current root session and release/handoff record in state. A resumed root may reuse this identity only after explicit handoff authorization and confirmation that the former session and children have settled; record old/new session identity and the evidence inside a locked update. A live or unknown prior writer blocks handoff. Release the root session assignment after settled closeout, preserving logical ownership and all state/report data. Never edit JSON around the helper to steal ownership.

## Root accounting

At baseline start, verify a commit and porcelain status with ignored submodule dirt excluded, then reject parent dirt, changed gitlinks, and unresolved operations. Inventory tracked/configured owned tests, disabled tests, packages, commands, runner/version, setup, fixtures, environments, type checks, coverage/mutation config, CI/history evidence, browser routes, and excluded independent repositories. Commands consuming dirty or unavailable children are blocked individually. Every owned test maps to a unit or explicit exclusion. Continue until every unit is reviewed, blocked, or skipped; no pending or stale unit may be hidden at close.

Set review order from evidence-based risk priority: destructive or stateful boundaries, authentication, persistence, concurrency, shared infrastructure, churn, regressions, and CI failures can move a unit earlier, while a user critical-area override wins. Priority never excludes a unit. Before admitting any command, record owning cwd, runner/version, exact arguments, discovery/source reference, selected scope, finite timeout, cleanup, and authorization class. Use 300 seconds initially unless repository configuration or observed runtime justifies another bound. Read the maintained runner documentation and repository configuration before interpreting mocks, timers, module mode, transforms, projects, or type checks. Do not install missing tools. Stop unclear, destructive, external, or live targets at authorization. A timeout requires diagnosis and safe child cleanup verification. Preserve bounded failed output and classify harness, product, external contract, or authorization failure before conclusions. Continue independent units and revisit failed units before closeout; unresolved failures remain explicit gaps, not product findings. Root-owned measurements run serially without overlapping review-owned workloads. Collect one ordinary sample per distinct safe available canonical measurement unit, recording duration, selected command scope, runner/version, instrumentation, and revision. One canonical measurement ID can be referenced by multiple clusters; incompatible inputs invalidate it once. Do not sum overlapping commands or invent attribution. A workflow share requires a compatible measured denominator and observable attribution; otherwise report unknown. Deep-performance mode distinguishes cold/warm repetitions, variability, available phase/slow-test data, coverage, type-check, and profiling overhead. Runner configuration experiments require separate remediation authorization.

Persist complete accounting, but cap each stored evidence excerpt at 4 KiB and mark truncation. Keep source, command/query, revision, version, scope, outcome, and limits with every evidence record. Expand Git history only after an observed churn, regression, origin, or maintenance signal justifies it; retain the source and timeframe. Expand reviewer context only after validating relevance and canonical containment. A context request never grants shell, mutation, delegation, or publication authority.

## Reconciliation and reporting

The root explicitly validates ownership handoff before dispatch, records the reviewer assignment and read paths, and confirms settlement before releasing the assignment. A child result is evidence only after settlement; it is not a lifecycle transition or closeout verdict. Do not duplicate summaries: derive report sections, status counts, gap lists, and evidence excerpts from the checkpoint records rather than persisting parallel aggregates.

Bind results to observed revisions. A changed test, source contract, fixture, setup, utility, configuration, dependency, or shared command invalidates affected units and dependents. Carry forward unaffected evidence only with an explicit Git comparison. Unknown dependencies, unavailable commits, or insufficient comparisons require refresh of affected units (all when impact is unbounded), never assumed validity. Dirty in-flight results are withheld. Additions and removals are reconciled; removed units remain historical records. Close only against one clean final commit and record original revisions, comparisons, measurement IDs, gaps, inventory set equality, and `closed-assessed` or `closed-with-gaps`.

Compose the report from state and include complete inventory accounting, reviewed symbols, commands/versions, evidence limits, checks not run, blocked/skipped scope, closeout revision/status, and a clear separation of verified defects, test-quality risks, maintainability advice, contract questions, smell candidates, no-change conclusions, and dispositions. Report protection, consequence, runtime share, flake evidence, and maintenance burden separately. Include every high-severity and highest-value medium finding in the primary section, other verified findings in an appendix, and shared findings once. No synthetic value/confidence score. Retain rejected candidates and their rejection reasons. In later diff reports, repeat an unresolved baseline finding only when it was touched, changed severity, or blocks the current change. Evidence records retain source or query, command, revision, relevant version/scope, outcome, and limits. CI/history references include source and timeframe. Existing coverage and targeted mutation are selective evidence for a named protection question, never targets or scores; run mutation only in an isolated disposable location that preserves the reviewed checkout. Reuse current coverage first; run configured coverage only for a specific unresolved protection/value question. Targeted configured mutation records mutant provenance and named behavior interpretation, including equivalence uncertainty. Already-configured authenticated CI may supply read-only timing, failure, retry, and flake evidence with source/timeframe. Missing tooling blocks dynamic evidence, and CI mutation, installation, credential disclosure, and generic-runner substitution are not permitted.

## Calibration

Calibration fixtures live outside ordinary discovery and are copied into disposable Git repositories. Root contracts and expected answers remain outside reviewer read authority. Exercise hidden regression, unique protection, redundancy, justified complexity/slowness, harmless weakness, and uncertain equivalence/unavailable runner cases with independent root counterfactual answers. The timeline is one root-driven sequence: absent baseline, shared-command clusters plus an independent control, partial checkpoint, interruption, committed unit/shared-setup changes and test add/remove, resume, dirty in-flight withholding, clean reconciliation, unchanged/gapped and limited modes, then the explicitly authorized fixture-only remediation demonstration. Record detections, omissions, false mandatory cleanup, unsafe accepted deletion, abstentions, candidate/verified separation, shared-finding deduplication, adversarial-content behavior, and measurement attribution. A miss or unsafe deletion rejects the bounded calibration; a justified abstention is not a miss. The root drives commands and verdicts and settles/cleans children before removing only owned disposable fixtures.

## Remediation

Require closed baseline and an explicit fix request. `closed-with-gaps` permits only verified findings independent of unresolved gaps; dependent findings remain blocked. Create one isolated remediation worktree from recorded final commit F, not current HEAD. Validate each unit and create focused commits without push, merge, rebase, or synchronization. Leave branch/worktree until the user supplies completion and integration/cleanup instructions; report divergence rather than synchronizing it. Behavior-preserving production seam changes are separate and must preserve public behavior; broader production refactoring needs a separate decision.
