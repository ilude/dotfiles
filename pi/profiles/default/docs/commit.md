# Quiet commits

`/commit` delegates the whole workflow to **openai-codex/gpt-5.6-luna**, at **low** reasoning: review, grouping/messages, staging, commits, and an optional push. An explicit operator request to commit may call `commit_run` directly with commit-only behavior. The current model presents its result without repeating routine Git work in the main conversation.

## What you see

- `/commit` and brief progress.
- Ignore questions for new files likely to belong in `.gitignore`, with explicit `Include in commit`, `Add to .gitignore`, and `Leave untracked` choices. The body shows the candidate, reason, and proposed rule; adding a rule updates that repository's `.gitignore` and the same Luna task resumes without a review restart. Cancelling a question stops the workflow.
- Any actual tool/provider/Git/hook failure, including the failed tool, repository/path or bounded shell-command excerpt, and elapsed time, followed by the current Git state. The first failure is preserved and blocks queued follow-up work; successful commits are not undone.
- One completion summary in the main response: actual `<short hash> <commit subject>` lines and `Pushed` only if applicable. Remaining changes, skipped files, or errors appear only when present; no clean-tree/not-pushed/“None” boilerplate. If nothing was committed, say so. The tool's progress disappears on successful completion, including when tools are expanded. The result still reaches model context; only the final reply displays it. Tool failures remain visible even if cancellation prevents a final reply.

Groups/messages need no approval. Unclear grouping defaults to one commit for eligible changes. Existing hooks run normally. No additional validation, secret-scanning phase, reports, path-accounting or staging-ambiguity gates are introduced. Every initialized submodule is reviewed as an independent repository. Dirty submodules are committed deepest-first, followed by refreshed parent gitlink status and commits. Detached repositories remain eligible for review and local commits; only publication skips them. Clean attached submodules with outgoing commits referenced by the current parent state are also published when push is authorized.

## Implementation

Before staging each repository, the reviewer runs `git diff --check`. Standard trailing-space diagnostics are repaired by the repository-owned `commands/commit/trim-trailing-whitespace.mjs` utility using only the reported text paths, then checked again. The utility preserves line-ending and final-newline style and rejects binary files; unexpected or unresolved diagnostics remain fatal.

`commit_run` owns one awaited, in-memory Pi `Agent`. It supplies root and initialized-submodule status plus tracked AGENTS.md paths directly and uses this profile's catalog/auth without changing the selected conversation model. Luna has paginated Git inspection, ordinary `read`/`bash` tools, and `ask_ignore`. The ignore tool requires an exact inventory repository, repository-relative candidate, reason, and conservative one-line proposed rule; `Add to .gitignore` serializes an exact-duplicate-safe append through `withFileMutationQueue` and returns an explicit instruction to refresh status and stage only `.gitignore`. Its prompt specifies tool-call examples, staged versus unstaged review, pagination, JSON-quoted inventory paths, explicit per-repository staging/commit commands, submodule order, and push branch/refspec handling. In push mode, the initial inventory also deterministically annotates each repository's attached branch and publication eligibility; Luna does not rediscover detached state. Initial status is already supplied; refreshes and diff inspection use `commit_git_review`, not improvised shell status commands. The task also supplies the absolute repository root and whitespace utility path; the utility accepts paths directly without a `--` separator. These instructions reduce avoidable command mistakes but do not guarantee model adherence or eliminate Git, hook, transport, or concurrency failures. Diff inspection accepts omitted or empty paths for all tracked changes in the selected inventory repository, or explicit paths to filter. `staged` selects index rather than worktree changes; untracked contents still require `read`. No summary-first prerequisite is required. Broad `find`, `rg --files`, and recursive `ls` discovery are blocked; Luna must use the supplied repository/instruction inventory. There is no extra filesystem sandbox or separate staging/commit executor. Its individual tool calls and reasoning are private on success. Failure-only diagnostics expose the failed tool and a shell-command excerpt of at most 300 characters.

The three-minute active-work budget pauses while waiting for an ignore decision. Git reads and shell commands retain 15-second timeouts. Transient provider and transport failures receive up to three provider retries before hard failure; Git, hook, cancellation, timeout, and other deterministic failures are not retried. Cancellation/timeout can leave completed commits or staging in place; after the task stops, read-only Git queries collect actual commits and remaining status from the root and initialized submodules, including on failure. Those reporting queries may extend elapsed wall time. The budget remains a target, not an atomic transaction or rollback mechanism.

Push permission is captured by the delivered `/commit push` invocation, not chosen by the main model's tool arguments. Direct `commit_run` calls and bare `/commit` both resolve to `push: false`; `/commit push` resolves to `push: true`. The profile binds delivered slash calls to immutable options so a later submission cannot change an already-bound call. Direct calls need no synthetic slash invocation and never inherit pending or stale push authority. Binding survives retries, compaction, and ordinary steering until the call result and command settlement; stale transcript details are never reconstructed into permission. Both slash forms request native `deliverAs: "steer"` delivery, including while another response is streaming. Bare/direct commit mode performs no publication-related branch, upstream, outgoing, remote, or push checks. In push mode, detached inventory entries are silently skipped without those checks or any warning/output; eligible attached repositories are checked and pushed from children before parents, including existing outgoing commits: `git push --recurse-submodules=no origin HEAD:refs/heads/<own-branch>`. The recursion override prevents inherited `push.recurseSubmodules=on-demand` from changing the coordinated order; it does not prohibit publishing submodules. Force-push and automatic merge/rebase remain excluded. As with ordinary shell use, these are agent instructions, not an OS permission boundary. Push failures do not undo local commits. An unavailable Luna produces an error, not a fallback model.

Only the final result enters main-model context. Successful nested usage is returned to Pi. No child session/report files are saved. Run `/reload` after code changes. Legacy is unchanged.
