# Commit Workflow

- Ownership: `/commit` is implemented by `pi/extensions/workflow-commands.ts` and `pi/lib/workflow-commands/commit-orchestration.ts`. Damage control independently governs Git commands invoked through shell tools.
- Planning: begin with non-mutating repository inspection. Select exact paths when only part of a worktree belongs in the commit. Unsafe repository states, unmerged paths, detached HEAD, and incompatible in-progress Git operations block mutation.
- Staging: stage only paths selected by the active workflow. Never force-add ignored paths. Preserve staged deletions, handle partially staged renames without passing the missing source path to `git add`, and reject an unexpected staged set.
- Creation: require a valid conventional subject, a whitespace-clean staged diff, and successful secret review. Commit creation is local and does not imply a push.
- Push: push only after an explicit user request. Require the expected workflow state, unchanged HEAD, an attached branch, and a non-diverged upstream. Use normal non-force push behavior.
- Submodules: treat each direct submodule as an independent repository. Commit and push it first, pull it fast-forward-only, then commit the parent gitlink. Never process nested submodules automatically.
- Failure: preserve the worktree and index on failure. A push failure after commit creation reports the push boundary and identifies commits already created instead of claiming that commit creation failed. Diagnose the failed boundary rather than bypassing preflight, staged-set, secret, upstream, or divergence checks. Recoverable local failures may provide one bounded automatic model handoff containing redacted failure context; the handoff is not permission to replay mutations or bypass safety, credential, submodule, or ownership controls.
